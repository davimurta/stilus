# 0002. Database access, site API keys and integration tests

Date: 2026-11-27
Status: accepted

## Decision

- **Driver:** `postgres` (postgres.js) with Drizzle. Works with any Postgres, including Neon's
  pooled connection string. Migrations are SQL files generated by `drizzle-kit` and committed.
- **Site API keys:** `stilus_sk_` + 32 random bytes (base64url). Stored as SHA-256 hex in
  `sites.api_key_hash`. A key is a random 256-bit token, not a human password, so stretching
  (argon2) adds latency on every text fetch without adding security. Comparison is
  constant-time, and an unknown site does the same work and returns the same `401` as a wrong key.
- **Revalidate secret** is stored in plain text: the central API must use it to sign webhook
  bodies. Protect it like any database secret.
- **User emails** are stored lowercase (check constraint) with a plain unique constraint.
- **Integration tests** call the exported route handlers (`GET(request, { params })`) with real
  `Request` objects against a real Postgres (`stilus_test`, docker compose, port 54329). No HTTP
  server, no database mocks. The schema is rebuilt from the migrations once per run, tables are
  truncated before each test, and files run serially.
- `pnpm check` starts the database with `docker compose up -d --wait`; CI uses the same compose
  file, so local and CI run the same Postgres.
